### ISR Write 소비 구조

**핵심 메커니즘**: 매 배포 시 ISR 캐시가 초기화됨 → 방문되는 모든 ISR 페이지가 다시 생성 → Write 소비

```
배포 1회당 ISR Write 소비 = 방문된 ISR 페이지 수

Google 크롤러가 sitemap 전체 크롤링 시:
  ~37,950 ISR 페이지 × 1 write = 37,950 writes/배포

월간 예산: 200,000 writes
  → 최대 5회 배포 가능 (37,950 × 5 = 189,750)
  → 6회부터 초과! (37,950 × 6 = 227,700)
```

## 전략 2: 사이트맵 분리 — 고우선순위 URL만 노출 (권장, 큰 효과)

**효과: ISR 소비 70-90% 절감**

### 현재 문제

사이트맵에 40,762개 URL이 모두 포함됨 → Google 크롤러가 모든 ISR 페이지를 방문 → 37,950 writes 소비

### 해결: 2-tier 사이트맵

**Tier 1 (sitemap-core.xml)**: SSG 페이지 + 고가치 ISR 페이지만 포함
- 모든 SSG 페이지 (2,812개)
- TOP 30 직업의 ISR 페이지 (~6,000개 추가)
- 합계: ~8,800개 URL
- Google에게 이 사이트맵만 제출

**Tier 2 (sitemap-extended.xml)**: 나머지 ISR 페이지
- priority: 0.3 (매우 낮음)
- Google Search Console에서 제출하지 않음
- 내부 링크로 자연적 발견 유도

### 대안: 사이트맵 URL 수 대폭 축소

현실적으로 **트래픽이 거의 없는 직업**(예: veterinarian, hvac-technician의 도시 비교)은 사이트맵에서 제외해도 SEO 영향 미미.

**제안: TOP 30 직업만 사이트맵에 포함**
- 30 × 42 = 1,260 (country pages)
- 30 × 98 = 2,940 (city pages)
- 30 × 40 = 1,200 (compare pages)
- 30 × 25 = 750 (compare-cities pages)
- 30 × 25 = 750 (relocate pages)
- 합계: 6,900 ISR 페이지 (현재 37,950 → **82% 감소**)
- 나머지 145개 직업은 `/browse` 페이지 내부 링크로 크롤링 유도

```
월 3회 배포: 6,900 × 3 = 20,700 ISR writes (예산의 10.4%)
월 5회 배포: 6,900 × 5 = 34,500 ISR writes (예산의 17.3%)
→ 매우 안전한 운영 가능
```

## 전략 3: robots.txt Crawl-delay 추가 (보조)

**효과: 크롤러 속도 조절로 일일 ISR 스파이크 방지**

```
# robots.txt에 추가
Crawl-delay: 10
```

- Google은 공식적으로 Crawl-delay를 무시하지만, Bing/Yandex 등은 존중
- Google의 경우 Search Console의 "크롤링 속도" 설정으로 조절 가능
- 일일 ISR writes를 균등 분배하는 효과

## 전략 4: SSG 범위 확대 — 불가능 (실측 확인)

**결론: 75MB Deploy Size 제한으로 SSG 확대 불가**

### 실측 데이터 (2026-02-22)

```
현재 SSG: 2,813 pages → 297MB (비압축) → ~51MB (압축)
페이지당 평균: 108.1KB (비압축)

TOP 20 시: +2,300 pages × 108KB = +248MB → 압축 ~94MB → 75MB 초과!
TOP 15 시: +1,150 pages × 108KB = +124MB → 압축 ~72MB → 위험 (96%)
```

SSG 확대는 현재 페이지 크기에서 불가능. TOP 10 유지 필수.

## 전략 5: 불필요한 ISR 페이지 제거 (선택)

### 후보: 트래픽 없는 조합 필터링

`generateStaticParams`에 `dynamicParams = false` 설정:
- 사이트맵에 없는 조합으로 접근 시 404 반환
- 봇/스크래퍼의 무의미한 ISR 생성 차단

```typescript
// 예: salary/[occ]/[country]/[city]/page.tsx
export const dynamicParams = false; // 사이트맵에 있는 조합만 허용
```

**주의**: TOP 10 직업만 `generateStaticParams`에 포함되므로, 나머지 165개 직업의 도시 페이지가 모두 404 됨.
→ 사이트맵 축소 전략과 함께 적용 시 일관성 유지 가능.

## FAQ

**Q: 사이트맵에서 빠진 페이지는 Google에 인덱싱 안 되나?**
A: 아닙니다. 내부 링크(`/browse`, 각 페이지의 Related 섹션)를 통해 자연적으로 발견됩니다. 사이트맵은 발견 속도를 높이는 보조 수단이지, 유일한 경로가 아닙니다.

**Q: TOP 30 직업은 어떻게 선정?**
A: GA4 트래픽 + Search Console 노출 + 검색량(BLS 직업별 고용자 수) 기반. 현재 TOP 10 + 추가 20개 (engineer류, 의료직, 비즈니스직).

**Q: 배포 횟수를 줄이면 버그 수정이 느려지지 않나?**
A: 로컬/dev에서 충분히 테스트 후 배치 배포. 긴급 보안 패치는 예외 허용.

**Q: 3월 1일 리셋 전에 배포하면?**
A: 현재 ISR Write 한도 초과 상태이므로 3월 1일 리셋 후 첫 배포 추천. 그 전에는 코드만 준비.
